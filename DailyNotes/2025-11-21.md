# Friday, November 21, 2025

## Summary of Findings for `[template].[Template_GetConfigurationGroupsOtherColumns]`

During the investigation into `[template].[Template_GetConfigurationGroupsOtherColumns]` returning multiple firmware versions, we analyzed a few approaches.

### 1. The Problem (As seen in `OLD CG OTHER.sql`)

The original query joined `template.Devices` to find the firmware version. A single template can have multiple devices (e.g., a MiX 4000 and a satellite module). This join structure caused the query to pick up the firmware version property from *all* associated devices, not just the main one. The results were then concatenated with `STUFF`, leading to outputs like "40.23, 1.12".

### 2. The Incorrect "Distinct" Fix (As seen in `Template_GetConfigurationGroupsOtherColumns_fixed.sql`)

A proposed solution added `SELECT DISTINCT` to the firmware version query. This would only work if the different devices shared the exact same firmware version. If a peripheral had a different version, `DISTINCT` would still return multiple rows, and the problem would persist. It was a superficial fix that didn't address the root cause.

### 3. The Correct Solution (As seen in `NEW CG OTHER.sql`)

The correct and simple solution is to only query for the firmware property associated with the **main device** of the template.

The `DeviceKey` for the main device is already determined in the `@GeneralConfigGroupInfo` table variable at the start of the procedure. The fix is to use this `DeviceKey` to filter the `[template].[DeviceProperties]` table directly.

This removes the faulty join to `[template].[Devices]` and guarantees that only the preferred firmware version for the main device is selected.

**Corrected FW Version Logic:**
```sql
  -- FW VERSION
  DECLARE @FWVersions TABLE  
    (
    [ConfigurationGroupId] BIGINT,
    [FWName]               NVARCHAR(50)
    );
  INSERT INTO @FWVersions
  SELECT
    [ConfigurationGroupId] = g.ConfigurationGroupId,
    [FWName] = fw.Name
  FROM @GeneralConfigGroupInfo g
    INNER JOIN [template].[DeviceProperties] tdpr WITH (NOLOCK)
    ON tdpr.MobileDeviceTemplateKey = g.MobileDeviceTemplateKey
      AND tdpr.PropertyKey = @FWVersion
      AND tdpr.DeviceKey = g.DeviceKey -- This is the correct filter
    INNER JOIN [definition].[FirmwareVersions] fw WITH (NOLOCK) ON fw.FirmwareVersionId = tdpr.Value
```
