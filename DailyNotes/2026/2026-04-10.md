## OPEN-2030 — Discord QC Bot — DONE ✅

### What was built
- AWS Lambda (Python) slash command bot: `/qc <IMEI>` triggers Powerfleet QC automation and posts results back to Discord
- Two Lambdas: `discord-qc-webhook` (handles Discord interactions, signature verification via PyNaCl) and `discord-qc-worker` (auth + QC API call + Discord response)
- API Gateway HTTP API endpoint hooked to Discord application

### Architecture
1. User types `/qc <IMEI>` in #qc-test
2. Discord POSTs to API Gateway → `discord-qc-webhook` Lambda
3. Webhook Lambda verifies Ed25519 signature, returns `{"type": 5}` (deferred — shows "thinking...")
4. Webhook Lambda async-invokes `discord-qc-worker` with `imei`, `application_id`, `interaction_token`, `channel_id`
5. Worker auths against MiX API, calls `/api/qc-automation/`, formats result
6. Worker tries PATCH `/webhooks/{app_id}/{token}/messages/@original` first, falls back to `POST /channels/{channel_id}/messages` with Bot token

### Root cause of 1010 errors
Cloudflare (fronts discord.com) was blocking all Lambda requests because no `User-Agent` header was set. Discord's API spec requires `User-Agent: DiscordBot (url, version)`. Adding this header resolved all 403/1010 errors immediately.

### Key fixes made during debugging
- PyNaCl: must use Linux manylinux wheels, not Windows wheels
- Discord public key: must be exactly 64 hex chars (32 bytes)
- QC API 400 = valid Fail result (not an error) — must catch HTTPError and read body
- Auth: real MiX auth call required (`/api/auth/token`)
- Bot install: must use Guild Install + `bot` scope (not User Install)
- `channel_id` must be passed from webhook Lambda to worker for fallback
- **User-Agent header**: required for all Discord API calls from Lambda

### Infrastructure
- Lambda: `discord-qc-webhook`, `discord-qc-worker` — eu-west-1, 512MB
- API Gateway: `https://dh02br6n8c.execute-api.eu-west-1.amazonaws.com/prod/discord`
- Env: INT (`https://automation-api.mixdevelopment.com`)

### Final QC API fixes (post-Swagger review)
- URL: removed trailing slash — `/api/qc-automation?` not `/api/qc-automation/?`
- Request body simplified to `UniqueIdentifier` + `ActionDate` only (Swagger confirmed extra fields unnecessary)
- `format_results` updated to show `Messages` summary + `TestAreas` grouped by area (Config, TripInfo, CommsInfo, etc.)
- Architecture diagram exported and attached to OPEN-2030 in Jira
